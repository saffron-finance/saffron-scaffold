1. Standalone application

The combined Home, Portfolio and Live APR interface includes mobile navigation and transaction dialogs. Production uses the canonical incentives API maintained in this repository. Configure real campaigns and operating owners before paid intake.

Open the app · Live APR · Portable source ZIP

2. Current lifecycle

Claim $X retains the incentive wording. A separate fixed native ETH fee configured per campaign on Robinhood requests automatic creation. Four verified stages lead to external premium funding, fixed-side LP entry, incentive claim and mature withdrawal.

Vault TVL values deposited campaign principal; APR keeps separate Pool TVL. Refund administration verifies full original-fee payouts paid externally. Private advisory targets do not cap requests.

Operators must set a positive fixed ETH request fee for each campaign. Fee edits apply to new quotes only; existing payment and refund amounts remain unchanged. No ETH/USD fee calculation is used.

Campaign IDs are assigned automatically. Pool token names replace custom campaign headings. Add pair uses two searchable token selectors, a swap control and verified existing fee tiers. The first token is the reward token. Token discovery uses the public CoinGecko list, a canonical fallback and read-only chain RPC; no CoinGecko key is required.

3. Install and run

Use Node 22.9 or newer and npm. Extract the source ZIP, enter its folder and run:

npm ci
npm run dev

npm run build writes the wallet/API application to dist/. build:lab adds appearance controls. Serve output through HTTP(S). No backend checkout is required to build the archive.

4. Live mode and routing

Put public settings in .env.local:

VITE_BASE_PATH=/
VITE_LIVE_APR_API_BASE=/api/live-apr/v2
VITE_UI_TWEAKS=false

npm run build:live writes dist-live/. Serve through the canonical backend with matching BASE_PATH and DIST_DIR. Configure its independent database, watcher and creator. Backend services and credentials are excluded from this frontend ZIP.

Preserve same-origin API/RPC/prices, cookies, unbuffered APR SSE, SPA routes and real missing-file 404s. Hosting provides staging access. Appearance controls never select the payment adapter; all builds require wallets for transactions and never fall back to samples.

5. Navigation and recovery

Home: /; Portfolio: /portfolio/vaults; operators: /campaigns and /admin; pool observations: /live-apr. Up to four pools can be compared.

Payment and position recovery survives reloads without automatic wallet sends. Full premium funding and actual ownership govern safe entry and later actions. APR outages remain explicitly unavailable while independently ready vault actions remain usable. There is no wallet-free preview or sample-data fallback.

WalletConnect enables mobile wallet links and desktop QR pairing when VITE_WALLETCONNECT_PROJECT_ID is configured before the live build. Configure Reown allowed HTTPS origins. Wallet browsers remain available. Qualify the real relay and supported phones before launch.

6. Application boundaries

One router, shell, theme and modal layer serve the public UI. Vendored sources and licenses are included. No other application is a build or runtime dependency. APR/PNG code loads when needed. The API and watcher are keyless; the separate creator only creates and initializes vaults. Premium and refund payments are external operator responsibilities.

7. Verification

 
npm run check:upstream
npm run test:source
npm run test:release
npm test
npm run typecheck
npx playwright install chromium
npm run build:live
npm run test:apr-http

For wallet/API UI checks, run build:lab, set SAFFRON_BACKEND_SOURCE and disposable SAFFRON_TEST_DB_* for a root mount and run test:browser. Follow docs/LIFECYCLE-ACCEPTANCE.md for the disposable backend tests on mobile and desktop.

Controlled HTTP/SSE tests qualify client behavior, not the deployed gateway. Hosted-browser, real phone, normal HTTPS clipboard and explicitly operated live-funds acceptance remain launch gates. Disposable time advancement does not establish real maturity.

8. Source and release identity

source-files.json defines the inventory. source-manifest.json records version, Git revision, normalized source digest and exact file hashes. Shared pins normalize CRLF to LF; archive integrity verifies exact bytes.

python scripts/verify_source.py
python scripts/render_install.py

The ZIP includes the lockfile, tests, portable scripts and licenses, excluding runtime settings, credentials, dependencies, build output and other ZIPs. Regenerate this guide from docs/install-guide.json.

Builds bind this source identity to the exact entry, asset manifest and lazy assets in deployment-mode.json. Include .vite/manifest.json when publishing. Pin the approved source manifest in the served-release checks described in docs/LIVE-CUTOVER.md.

9. Release and rollback

Follow docs/DEPLOYMENT.md and docs/LIVE-CUTOVER.md. Build identity does not establish publication or enabled intake. Verify the intended candidate through existing hosting access before cutover.

Publish hashed assets before the entrypoint and retain old assets for open tabs. Preserve database/WAL, received fees, watcher cursors, journals, permits and browser recovery. Use a backend compatible with advisory commitments and refund closure. Do not restore the old hard-cap schema or reset QA for a frontend release.

Navigation: Home, Portfolio, Saffron pro, Live APR. Live APR uses the APR text effect without changing its font. Amount/review primary buttons share the selected sidebar background, including browser-local appearance settings.

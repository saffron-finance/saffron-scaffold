2. Latest incentives changes and the plan

Version 0.2.0 integrates applicable product changes from all 26 commits between 93fcab6 and 19ad0e9. The earlier watcher/VNC release did not update this separate frontend.

  • C06 shows four stages, elapsed time and recoverable progress.
  • Live mode uses canonical payment recovery and current position ownership.
  • Public capacity meters and request limits are removed. The planning advisory appears only in admin Portfolio.
  • C05, refund/retirement controls, gas-spending records and treasury tracking are absent.
  • Approved navigation, modal styling, Live APR observations and PNG export remain.

The source includes a commit-by-commit integration map in docs/PRODUCT-SYNC.md.

3. Install and run

Use Node 22.9 or newer and npm. Extract the source ZIP, enter its folder, and run:

npm ci
npm run dev

Preview builds need no backend checkout. Run npm run build for the normal preview, or npm run build:lab for Tweak controls. Serve dist/ through HTTP(S), not a file URL.

4. Hosting, base paths and live data

For this nested preview, set these public values in .env.local, then run npm run build:lab. The same instructions apply on Windows.

VITE_BASE_PATH=/saffron/apps/feature-lab/live-apr-merge/
VITE_LIVE_APR_API_BASE=/saffron/api/live-apr/v2
VITE_FEATURE_LAB_HREF=/saffron/apps/feature-lab/

For a root install, use VITE_BASE_PATH=/. Preserve authentication, SPA fallback for extensionless routes and genuine 404s for missing files. API paths must not fall through to HTML. Clipboard PNG requires HTTPS or localhost.

API mode: npm run build:live writes dist-live/. Serve it through the canonical liquidity-incentives backend with matching base path and DIST_DIR. This mode enables real wallet actions; the default preview cannot switch into it at runtime. Backend services and credentials are not included in this ZIP. See docs/DEPLOYMENT.md.

5. Routes and persistent state

Sidebar order: Home, Portfolio, Saffron pro, Live APR, Stats, Audits, Community.

  • /: incentive offers.
  • /portfolio/vaults: saved requests and owned positions.
  • /campaigns and /admin: operator controls.
  • /live-apr: NVDA / USDG 0.05% default; pool and comparison routes remain supported.
  • /stats and /community: scaffold pages without invented live statistics.

Existing sample storage stays under saffron.live-apr-merge.campaign-preview.v1. Requests and edits survive this update. Reset preview affects only this key. Sample C06 is labelled and has no chain receipts. API mode uses shared backend state and durable local payment-recovery records; no preview reset is offered.

APR observations release on section exit and restart with fresh baselines on return. Sidebar preferences, dark styling, collapsed-rail behavior and the lab NEW-on-left toggle remain.

6. Component reuse and dependencies

One router, shell, theme and modal layer serve both sections. APR and PNG code remain lazy. The preview build excludes wallet discovery and actual request transport. The live build uses the canonical wallet adapters and payment hooks.

Nine runtime dependencies remain; no new package was needed. Backend PostgreSQL, watcher, creator and recovery tools stay in the canonical repository.

7. Reproducible checks

 
npm test
npm run check:upstream
npx playwright install chromium
npm run build

For a root build, set MERGE_BASE=/ and run npm run test:browser. The suite checks actual compiled layouts, APR wire fixtures, PNG pixels, multiple requests, private advisories and storage preservation. Use the nested build without this override.

npm run test:backend-browser requires build:live at base / and SAFFRON_BACKEND_SOURCE pointing to the canonical package. Configure its disposable PostgreSQL test fixture as documented there. It uses generated wallets and a local EVM, with a separate fork simulation before reviewed creation. It exercises payment recovery, C06, premium funding, LP deposit, claim, dates and withdrawal. No live funds or VNC reset are involved.

This release was checked on Linux. Portable Windows build instructions are not a claim of a new Windows end-to-end test. Fixture tests are not mainnet tests.

8. Source map and provenance

src/merge owns routing and build-mode entry. src/host owns the shell and canonical hooks. src/incentives owns product screens. src/preview is local-only; src/adapters serves API mode. src/livePoolApr remains the pinned APR module.

Current incentives compatibility: 19ad0e90af221e86fd13014b5d7e7aceb9a05cc9. APR source: b8eb411f435a1e0d0529dd77f15e117fb6be2f7f. Original source hashes are retained. docs/upstream-sync.json pins exact imports; the ZIP manifest hashes the final package. Credentials, installed dependencies, build outputs and backend services are excluded.

9. Deployment boundary and rollback

Back up the current published static files and route configuration before replacing them. A Git rollback alone does not restore a deployed build. Publish hashed assets before the entrypoint; retain old assets for open tabs.

Restore the previous entrypoint and static manifest to roll back. Keep authentication and APR routes unchanged. Do not clear browser storage, reset VNC or restore databases for a static frontend rollback.

See README.md and docs/DEPLOYMENT.md in the source ZIP for the maintained procedure. Rebuild this HTML from docs/install-guide.json with scripts/render_install.py.

Navigation: Home, Portfolio, Saffron pro, Live APR. Live APR uses the APR text effect without changing its font. Amount/review primary buttons share the selected sidebar background, including browser-local appearance settings.
